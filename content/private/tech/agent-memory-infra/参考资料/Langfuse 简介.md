

**Langfuse** 是一个开源的 **LLM 可观测性平台（LLM Observability Platform）**，核心功能包括：

| 功能 | 说明 |
|------|------|
| **Trace/Span 追踪** | 记录 LLM 调用的完整链路（请求、响应、延迟、Token 消耗） |
| **Prompt 管理** | 版本化管理 Prompt，支持 A/B 测试 |
| **评估（Evals）** | 对 LLM 输出进行自动化评估和打分 |
| **数据集与实验** | 管理测试数据集，运行离线实验 |
| **成本分析** | 统计各模型、各应用的调用成本和用量 |
| **多模态支持** | 支持图像、音频等非文本输入的追踪 |

## 在 AMS 系统中的可能位置

根据你的 [[private/tech/agent-memory-infra/最新技术方案-版本C/00-概要设计.md|AMS 概要设计]]，Langfuse 可以在以下位置发挥作用：

### 方案 1：作为 Agent-TES 的上游数据源

```
┌─────────────────────────────────────────────────────────────┐
│  Agent Framework (LangChain/CrewAI/自研)                     │
│       │                                                     │
│       ▼                                                     │
│  ┌─────────────────┐      ┌──────────────────────────────┐ │
│  │   Langfuse SDK  │─────→│      Langfuse Server         │ │
│  │  (轻量埋点)      │      │  (追踪存储、UI、分析)          │ │
│  └─────────────────┘      └──────────────┬───────────────┘ │
│                                          │                 │
│                                          ▼                 │
│                              ┌──────────────────────┐     │
│                              │   OpenTelemetry      │     │
│                              │   Exporter          │     │
│                              └──────────┬───────────┘     │
└─────────────────────────────────────────┼─────────────────┘
                                          │
                                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Agent-TES (你的系统)                      │
│              (统一遥测数据归一化与路由)                       │
└─────────────────────────────────────────────────────────────┘
```

**适用场景**：
- 如果你希望**渐进式引入**可观测性，先用 Langfuse 快速搭建
- Langfuse 收集的 Trace 数据通过 OTel Exporter 流入你们的 Agent-TES

### 方案 2：作为 Agent-TES 的替代方案（功能重叠）

对比：

| 维度 | Agent-TES (你的设计) | Langfuse |
|------|---------------------|----------|
| **采集方式** | Sidecar/eBPF/字节码插桩（非侵入） | SDK 嵌入（侵入式） |
| **数据范围** | 全链路（LLM + 工具 + 业务） | 主要聚焦 LLM 调用 |
| **数据去向** | Kafka → Memory Lake | 自带存储，可导出 |
| **记忆集成** | 原生设计，直接流入 Declarative/Procedural Memory | 需二次开发对接 |

**⚠️ 注意**：你的 ADR-005 明确选择了 **Sidecar 模式而非 SDK 嵌入**，这与 Langfuse 的标准集成方式有冲突。

### 方案 3：Langfuse 仅用于开发调试，不进入生产数据流

```
开发/测试环境：
Agent Framework → Langfuse SDK → Langfuse UI (开发者查看)
                                          ↓
                                    (手动导出)
                                          ↓
                                    测试数据集 → Skill-DOM 沙盒测试
```

## 建议的定位

基于你们的设计原则，我建议：

| 场景 | 建议 |
|------|------|
| **生产环境核心采集** | 使用 **Agent-TES**（符合非侵入式原则） |
| **开发调试/快速原型** | 使用 **Langfuse**（快速查看 Trace） |
| **数据互通** | Agent-TES 支持 **OpenTelemetry** 标准，Langfuse 也支持 OTel，可以互通 |
| **Skill-DOM 评估** | Langfuse 的 Evals 功能可用于 Skill 的沙盒测试阶段 |

### 在文档中的位置

如果你要引入 Langfuse，建议在第 12 章（可观测性）中增加：

```markdown
## 12.3 开发期可观测性工具（可选）

### Langfuse 集成（非生产环境）
- **用途**：开发阶段快速调试 Agent 行为
- **部署**：Docker Compose 本地部署
- **数据隔离**：开发/测试数据不流入生产 Memory Lake
- **与 Agent-TES 关系**：通过 OpenTelemetry 协议桥接，Langfuse 作为临时 Collector
```

## 总结

- **Langfuse** = LLM 可观测性工具，适合**开发和轻量级生产场景**
- **在你们系统中** = 可作为 **Agent-TES 的补充**（开发调试），但不宜替代（违背非侵入式原则）
- **数据流向** = Langfuse 追踪数据 → OTel → Agent-TES → Memory Lake（如果需要的话）
