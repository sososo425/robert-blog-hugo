## 一、概念本质

**情景记忆（Episodic）**——记的是"一件具体发生的事"，带时间戳、带上下文、带偶然性。人类对应：你记得上周三你在哪家餐厅吃了什么。

**语义记忆（Semantic）**——记的是"关于世界的稳定知识/事实"，去掉了时间和情境。人类对应：你知道巴黎是法国首都，但你不记得你是从哪篇文章里学到这个的。

在 agent 系统里，两者的核心区别是：情景记忆保留了"发生的过程和偶然细节"，语义记忆是从多次事件中提炼出来的"通则性结论"。

---

## 二、从哪来、如何提取

**情景记忆的来源和提取**

原始来源就是 agent 运行时的事件流——每一轮对话、每一次 tool call、每一次任务执行结果。提取方式相对粗暴：直接把这段对话/事件 chunk 向量化，打上时间戳存入 Vector DB，几乎不做加工。关键设计点在于粒度——是按轮次切，还是按"一次完整任务"切，会直接影响后续召回质量。

**语义记忆的来源和提取**

语义记忆不能直接从单次对话里提取，它需要一个"蒸馏"过程。通常有两种触发方式：

一是 session 结束后，用一个专门的 LLM prompt 对刚才的情景记忆做反思，比如："从这段对话里，你能推断出用户有哪些稳定的偏好或事实？"，输出结构化的 `{entity, attribute, value}` 三元组。

二是多轮观察后的归纳——比如用户三次都拒绝了 bullet point 格式，这个模式被检测到后才写入"user.prefers_format = prose"。

这就带出一个关键问题：**语义记忆的提取本质上是一个有损压缩**，你在压缩时会丢失情景的偶然性细节，这些细节有时候非常重要。

## 三、应用场景与典型例子

**情景记忆的典型应用场景：**

- 个人助理 agent 记住"上次帮你写的方案最后被老板打回来了，原因是数据引用不够严谨"
- 编程 agent 记住"上次这个 PR 用户改了三次才通过，核心卡点是测试覆盖率"
- 客服 agent 记住"这个用户上个月投诉过一次，最终给了补偿券"

**语义记忆的典型应用场景：**

- 记住用户偏好：写作风格、语言、专业领域
- 记住用户的基础背景："这个用户是后端工程师，熟悉 Go 和 Kubernetes"
- 记住实体关系：用户的团队成员、常用工具链、项目代号

## 四、哪些问题只能靠情景记忆，语义记忆回答不了？

这是最核心的一个问题。大致有三类：

**1. 需要追溯"具体过程"的问题**

> "上次我们讨论架构方案时，你当时给了哪几个选项？" "我上个月让你帮我改的那封邮件，当时原文是什么？"

语义记忆只知道"用户曾经讨论过架构"，但具体选项是什么、原文是什么，这些细节在蒸馏时被丢掉了。情景记忆保留了原始 chunk，能直接回答。

**2. 需要判断"时序和因果"的问题**

> "我是先告诉你不要用 React，还是先告诉你项目要兼容 IE11？" "上次任务失败是在哪一步出的错？"

语义记忆是无序的知识图谱，"user.no_react = true"和"user.ie11_compat = true"都在里面，但谁先谁后、是否有因果关系，语义记忆完全无法回答。

**3. 需要处理"偏好发生了变化"的问题**

> "我之前是说不要加注释，但上次那个项目我改主意了，那次之后你要默认加注释。"

语义记忆存的是当前的结论"user.comments = false"，它不记得这个值被覆盖的历史。如果用户的新指令模糊，agent 需要回溯情景记忆看"用户在什么背景下做了什么决定"，才能正确处理冲突。

**4. 需要还原"情绪/态度/语气"的问题**

> "上次我对这个结果满意吗？" "用户之前对这类回答有没有明显不满过？"

用户的满意度、情绪反应是不会被提炼进语义记忆的。这些信号藏在情景记忆的原文里——"用户说了'算了随便吧'"这句话，它的语义是敷衍，语义记忆提炼不出这种细微信号，只有回去翻原始对话才能判断。

## 五、一句话总结两者的关系

语义记忆是情景记忆的**有损摘要**，换来的是检索速度快、注入成本低。代价是丢失了时序、细节、偶然性。两者必须配合——先用语义记忆快速定位用户画像，再用情景记忆补充具体细节，才是完整的 memory 系统。
