基于对 Group3 文档和三篇论文分类文章的分析，我的判断如下：

---
### 核心理由

**1. 存储的对象是知识性/事实性信息，而非技能或策略**

Group3 的核心任务是从 Session/Trace 中抽取：
- **实体**（人、工具、概念、文件）
- **事件**（用户请求、工具调用、问题、解决方案）
- **关系**（`uses`、`mentions`、`related_to`）
- **时间信息**（时间戳、先后顺序）

这些都是"**发生了什么、谁和谁有关**"这类事实性知识，对应的是论文综述中 Factual Memory 的定义："存储知识和事实信息"。

**2. 它不是经验记忆**

经验记忆关注的是"**从失败/成功中学到的策略、洞察和可复用技能**"——如 Reflexion 的自我反思、ExpeL 的经验提炼、SkillWeaver 的技能发现。Group3 不做反思、不提炼策略、不积累技能，它做的是**结构化知识沉淀**。

**3. 它不是工作记忆**

工作记忆关注的是"**当前会话内的上下文管理、注意力调控**"——容量有限、临时存储、服务当前推理。Group3 明确定位为**跨会话、跨轮次的长期记忆**组织骨架，是持久存储，这正是 Factual Memory 的范畴。

### 更精确的定位

如果用论文综述的分类框架来标注：

| 维度 | Group3 的定位 |
|------|-------------|
| **功能 (Function)** | **Factual Memory** — 存储实体、事件、关系等知识性信息 |
| **形式 (Form)** | **Token-level** (Raw Block, 自然语言) + **Latent** (Milvus 向量) 的混合 |
| **动态 (Dynamics)** | **Formation** (信息提取和编码) 为主，涉及少量 Evolution (实体链接/消歧) |

### 最接近的参考论文

在 Factual Memory 分类中，Group3 的设计思路与以下论文高度对齐：
- **HippoRAG** — 同样受认知科学启发，结合语义索引和拓扑图索引
- **MAGMA** — 基于多图结构的记忆架构（语义图、情景图、实体图分离）
- **Mem0** — 生产级可扩展长期记忆系统，支持多层级存储

### 补充说明

Group3 的 Temporal KG 中虽然包含**事件（EventNode）**和**时序边（precedes/follows）**，这些看起来有点像"经验记忆"中的情景记忆（Episodic Memory），但关键区别在于：
- Group3 只是**记录事件发生的事实**（"什么时候调用了什么工具"），属于事实层面的时间线建模
- 经验记忆中的情景记忆强调的是**从事件中提炼洞察和策略**（"调用这个工具失败了，下次应该怎么做"）

所以 Group3 是 **Factual Memory 中偏 Episodic/Temporal 的子类**——它记录事实性的事件序列，但不做经验提炼。

## 核心回答：这是两套不同的分类体系，而且 Group3 当前只做到了"半程"

### 1. 两套分类体系的关系

你提到的其实是两套分类框架在交叉：

**认知心理学经典分法：**
```
长期记忆
├── 陈述性记忆 (Declarative)
│   ├── 语义记忆 (Semantic) — "Python 是编程语言"
│   └── 情景记忆 (Episodic) — "昨天用户用 pandas 处理了 CSV"
└── 程序性记忆 (Procedural) — "处理 CSV 的标准流程是..."
```

**论文综述（复旦团队）的分法：**
```
Agent Memory
├── Factual Memory — 存储知识和事实（≈ 语义记忆 + 情景记忆的原始记录）
├── Experiential Memory — 技能、策略、洞察（≈ 程序性记忆 + 反思提炼）
└── Working Memory — 当前上下文管理（≈ 短期/工作记忆）
```

**这两套分法并不是简单的一一映射**，关键的错位在于：

> **情景记忆（Episodic）在两套体系中被拆开了。**

- "昨天调用了 read_excel，成功了" → 这是**事实性的事件记录**，归 Factual Memory
- "从多次调用 read_excel 的经历中总结出：处理 Excel 前应该先检查文件编码" → 这是**从情景中提炼的洞察**，归 Experiential Memory

### 2. Group3 当前做的事 vs 经验记忆的边界

你说得对——**Group3 提取的 tool use 流程确实是经验记忆的原料**。但问题在于 Group3 当前的 pipeline 停在了哪一步：

```
Session/Trace
    ↓
[Group3 当前做的] 结构化抽取
    ↓  实体、事件、时序边、tool use 记录
    ↓  "用户调用了 python_executor → read_excel → 成功"
    ↓
    ↓  ← ——— 分界线 ——— →
    ↓
[Group3 没做的] 经验提炼
    ↓  模式识别、策略总结、技能封装
    ↓  "处理 Excel 的标准技能：1.检查编码 2.选择引擎 3...."
    ↓
    ↓  复用与改进
    ↓  "新任务匹配到已有技能 → 调用 → 反馈 → 技能优化"
    ↓
Experiential Memory（经验记忆）
```

所以更准确的说法是：

> **Group3 构建的是"事实性的情景记录层"——它是经验记忆的前置基础设施，但它本身还不是经验记忆。**

用一个类比：
- Group3 ≈ **写日记**（记录发生了什么、什么顺序、谁参与了）
- Experiential Memory ≈ **从日记中总结人生经验**（提炼模式、形成策略、变成可复用的技能）

### 3. 对应到论文看得更清楚

| 层次 | 做的事情 | 对应论文 | Group3 是否覆盖 |
|------|---------|---------|--------------|
| **事件记录** | 记录 tool call 轨迹、参与实体、时间线 | HippoRAG, MAGMA | ✅ 覆盖 |
| **经验提取** | 从轨迹中提取成功/失败模式 | ExpeL | ❌ 没做 |
| **策略反思** | 总结"为什么失败、下次怎么做" | Reflexion | ❌ 没做 |
| **技能封装** | 将流程封装为可复用的技能模板 | SkillWeaver, Agent Workflow Memory | ❌ 没做 |
| **技能进化** | 根据新经验更新技能 | MemEvolve, Remember Me Refine Me | ❌ 没做 |

### 4. 所以结论是

**Group3 在两套分类体系中的定位：**

```
认知心理学视角：
  Group3 = 情景记忆（Episodic Memory）的结构化记录层
  → 记录了"发生了什么事"，但没有从中"学到什么"

论文综述视角：
  Group3 = Factual Memory（偏 Episodic 子类）
  → 是 Experiential Memory 的上游原料供应商
  → 但要再往下走一步（模式提炼 → 技能封装 → 复用改进）
     才能映射到 Experiential Memory
```

**你的直觉是对的**：Group3 抽取的 tool use 流程"天然可以"沉淀为复用技能。但"可以沉淀"和"已经沉淀"是两件事。当前 Group3 的设计停在了**记录**层，还没有进入**提炼**层。如果后续在 Temporal KG 之上加一层经验提炼模块（类似 ExpeL 或 SkillWeaver 的做法），那才算真正跨入了 Experiential Memory 的领地。

这也恰好对应了 Group3 文档中"后续演进"部分提到的方向——当前原型先把骨架搭好，经验提炼是自然的下一步。
